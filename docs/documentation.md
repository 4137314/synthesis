# API documentation and publication

The public API is generated by [doc-gen4](https://github.com/leanprover/doc-gen4),
using a separate `docbuild` project as recommended upstream. Its pinned commit matches
Lean 4.32.2. The root project uses Mathlib's matching release; both dependency closures
are recorded in committed Lake manifests. Documentation tools are not dependencies
of downstream library consumers.

## Build and preview

```sh
nix develop
bash scripts/cache.sh
bash scripts/check.sh
bash scripts/docs.sh
python3 -m http.server --directory docbuild/.lake/build/api/doc 8000
```

Open http://localhost:8000. A web server is needed for search and other browser features;
opening HTML files through `file://` is insufficient. The documentation includes every public kernel, domain and bridge module. The pinned
doc-gen4 `single` and `fromDb` commands extract project modules serially; external module
links point to the upstream Mathlib documentation instead of regenerating its entire API.
`scripts/check_docs.py` rejects missing public module pages or missing search data.
Generated files are excluded from Git. Automatic equation sections are disabled with
`DISABLE_EQUATIONS=1` to avoid expensive synthesis for imported compiler definitions.
Signatures, theorem statements, docstrings, search and source links are still generated;
this presentation setting does not change any library proof or its audit.
Generation defaults to two Lean worker threads and one project-module extractor at a time.
Set `SYNTHESIS_DOC_THREADS` explicitly only when the runner has sufficient memory.

The Nix development shell disables `bindnow` hardening: the pinned UnicodeBasic
dependency uses Lean module plugins with lazily resolved C symbols. Eager binding
fails on clean builds with `undefined symbol: unicode_script_to_abbrev`. Other Nix
hardening defaults remain enabled. After changing this setting, rebuild that dependency
with `lake -d docbuild clean UnicodeBasic` before generating documentation again.

## GitHub Pages

The repository uses the GitHub Actions publishing source. CI verifies the library and
its proof assumptions, generates documentation, and uploads the Pages artifact only
for `main` builds. The deployment job needs successful completion of that build and
has only Pages-write and identity-token permissions. Pull requests build documentation
but cannot deploy it. Workflow actions are pinned to full commit hashes.

The published site is https://4137314.github.io/synthesis/.
The deployment uses GitHub's [custom workflow mechanism](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
For a fork, enable Settings → Pages → Source → GitHub Actions and update the site URL
in the repository documentation. No personal token belongs in the workflow or repository.

## Updating dependencies

Choose Mathlib and doc-gen4 revisions compatible with the selected Lean release, then
update the corresponding `rev` entries before running:

```sh
MATHLIB_NO_CACHE_ON_UPDATE=1 lake update mathlib
MATHLIB_NO_CACHE_ON_UPDATE=1 lake -d docbuild update synthesis doc-gen4
bash scripts/cache.sh
bash scripts/check.sh
bash scripts/docs.sh
```

Review and commit `lean-toolchain`, `lakefile.toml`, `lake-manifest.json`,
`docbuild/lakefile.toml`, and `docbuild/lake-manifest.json` as applicable. The documentation
project shares package storage with the root; its Mathlib revision must match the root
manifest. Do not run unpinned dependency updates during CI.
